Rewrite your previous response — plus anything it points to in the
same turn, like a findings list "above" — as the shortest version
that keeps every fact I'd act on. Work only from what you already
said: no tools, no new research.

**Triage each sentence of the source:**
- *Load-bearing* → keep: answer/verdict, decisions, findings, numbers,
  identifiers, commands, next actions, open questions, corrections
  to earlier claims, and confidence ("unverified", "likely").
- *Pointer-able* → replace with a reference: `path:line`, or a PR,
  ticket, or doc link reused from the source.
- *Scaffolding* → drop: narration of what you did, restated context,
  transitions, ruled-out options, hedges that don't change the action.

**Output, in order:**
1. Bottom line — one sentence, verdict in **bold**.
2. Body — each load-bearing fact once, in the shape that fits it:

   | Source content | Shape |
   |---|---|
   | Findings / issues | ranked bullets, `**Label:** detail` + `path:line` |
   | Options or items with ≥2 attributes | table |
   | Cause → effect, data flow, sequence | `A → B → C`; ASCII diagram in a code block if it branches or has ≥4 steps |
   | Steps to run | numbered list, commands in code blocks |
   | Status across items | done / open / blocked groups |
   | Several topics | short bold label per topic |

3. **Next:** or **Needs you:** — when the source has actions or open
   decisions.

**Language:** plain words, active voice, one fact per bullet. Digits
with units (`2.3% CPU`, `19h`). Identifiers, commands and error text
verbatim in backticks. Qualifiers that change the action stay as a
tag: `(unverified)`. Links as `[#6621](url)` using URLs from the source.

Length falls out of the triage — typically about a third of the source.
If the source is under ~100 words, reply with one line saying it's
already short, plus its bottom line.

Before sending, re-scan the source: every load-bearing item appears.

**Audience (`$ARGUMENTS`):**
- `slack` — paste-ready Slack mrkdwn: `*bold*`, `•` bullets,
  `<url|label>` links, no tables or headings, arrows instead of
  diagrams. Output text only; don't send anything.
- `pm` — outcomes, dates, and ticket/PR links; no file paths or code
  identifiers.
- anything else — write for that audience.
