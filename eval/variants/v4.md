Rewrite your previous response as a tldr: about a quarter of its
length, keeping every fact I'd act on. The source is that response
plus anything it points to in the same turn (e.g. a findings list
"above"). Every statement in the tldr traces to a sentence in the
source — no tools, nothing added from elsewhere in context.

**Triage each sentence of the source:**
- *Load-bearing* → keep, compressed to what + where + status/number:
  answer/verdict, decisions, findings, numbers, identifiers, actions
  and open questions the source states, corrections to earlier
  claims, confidence ("unverified", "likely").
- *Explanation* → a clause of ≤10 words when it changes what I'd do;
  otherwise a pointer: `path:line`, a PR/ticket link from the source,
  or "(commands above)".
- *Scaffolding* → drop: progress narration, restated context,
  transitions, ruled-out options, hedges.

**Output, in order — each fact appears once:**
1. Bottom line — one sentence, verdict in **bold**.
2. Body, in the shape that fits:

   | Source content | Shape |
   |---|---|
   | Findings / issues | ranked bullets: `**Label (severity):** outcome — path:line` |
   | Items with ≥2 attributes (status, options) | table |
   | Cause → effect, sequence, data flow | `A → B → C`; ASCII diagram in a code block if it branches |
   | Answers to a list of questions | one line per question, same numbering |
   | Steps to run | numbered list; key command inline, long blocks → "(commands above)" |
   | Several topics | short bold label per topic |

3. **Needs you:** — only decisions or inputs the source asks of me.

**Language:** plain words, active voice, one fact per line. Digits
with units (`2.3% CPU`, `19h`). Identifiers and error text verbatim in
backticks. Qualifiers that change the action stay as a tag:
`(unverified)`. Links as `[#6621](url)`, reusing URLs from the source.

**Length:** 20–35% of the source. Over budget → shorten explanations
first, then merge same-kind items onto one line. Source under ~100
words → one line saying it's already short, plus its bottom line.

Before sending, re-scan the source: every load-bearing item appears,
and every fix, next step, count and caveat in the tldr is one the
source states.

**Audience (`$ARGUMENTS`):**
- `slack` — Slack mrkdwn inside a ```` ```text ```` block so the markup
  survives copying: `*bold*`, `•` bullets, `<url|label>` links, arrows
  instead of tables or diagrams. Output only; send nothing.
- `pm` — outcomes, dates, ticket/PR links; no file paths or code.
- anything else — write for that audience.
